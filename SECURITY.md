# Security policy

## Supported version

Security fixes are applied to the current `main` branch. This repository does
not maintain older release lines.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's
private **Report a vulnerability** option under the Security tab. Include the
affected component, reproduction conditions, impact, and any suggested
mitigation. Avoid including credentials, tokens, personal data, or live customer
information.

If private reporting is unavailable, contact the repository owner through the
address on their GitHub profile without sending exploit details in the first
message.

## Scope and data handling

The application is designed for fictional policies and synthetic support data.
Do not submit real payment, identity, account, or customer data. A deployed demo
should use temporary AWS credentials, bounded usage controls, and the documented
teardown procedure.
